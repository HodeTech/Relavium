The keymap is decided in one pure reducer and is covered by automated tests on every platform. What a test cannot show is what a **Windows console** actually delivers: whether `Ctrl+C` in raw mode arrives as a key (the keymap applies) or as a SIGINT (the signal path of ADR-0115 §4 applies instead). This recipe records which one it is, and that the keymap still behaves as designed under it.

## What you need

- A Windows 10 or 11 machine, a built `relavium` (the installed package or `node apps/cli/dist/index.js`), and a provider key in the Windows credential store.
- **Two terminals**, one each from: Windows Terminal (PowerShell) and the legacy console host (`cmd.exe` in a classic conhost window). Repeat the checks in both; the answer can differ.
- A throwaway directory as the working directory. Row 10 needs a `.relavium/project.toml` in it (create the file; nothing else about a project is needed).
- Use a small, quiet model; the turns below are one line each.
- Rows 17 to 19 need a workflow in the throwaway project that **runs long enough to press keys in** (a minute or more: a chain of agent nodes on a small model, each asked for a few hundred words), and the `/run` card flow of the Home (`/run`, pick the workflow, answer its inputs, press `Ctrl+Y` at the confirmation). A second terminal runs `relavium status <run id>` (the id is in the view's title) to see what the run is doing without going through the Home.
- Rows 20 to 24 need two more workflows in the throwaway project: one with a `human_gate` node (`gate_type: approval`) after a short agent node (the run pauses at the gate), and one whose workflow `budget` is so low that its first agent step pauses at a budget gate (use a small model). Start each with `/run`; the run view shows `‖ paused` when it parks. The Home must be opened in that directory: a run of another directory has no row and no card.

- Rows 26 to 30 and 42 to 45 need, in the throwaway project, **a workflow that finishes** (one short agent node), **a workflow that fails at its second node** (for instance a `transform` that refuses its input, after an agent node that succeeds), **a workflow whose agent node retries and then succeeds** (a node `retry` budget above zero and a task a small model sometimes gets wrong, or a tool that fails once; if none can be produced, record row 30's retry check as unrun), and **one node whose answer is long** (ask for sixty numbered lines). Run each once from the Home with `/run`, so that History lists finished runs of this project. The Home must be opened in that directory: the Runs screen lists this directory's runs by default. Row 45 also needs one run recorded from another directory.

- Rows 46 to 50 need only the throwaway directory with a small text file in it (a few lines, for instance `notes.txt`, that the model can read with `read_file`, so that a tool row appears), a window you can resize and a mouse. Rows 46 to 48 and 50 use the full-screen renderer (the default); row 49 uses `--no-alt-screen`.

- Rows 51 to 59: row 51 needs a Home with **no usable provider key** (no credential-store entry for any provider, none of the provider environment variables) and a global config you can delete and recreate, so run it first, or in a second Windows user; row 52 needs a Home that has a key. Row 53 needs an empty directory with no `.relavium/`. Rows 54 and 55 need a chat with a finished turn and, for row 55, at least two saved sessions in this directory and one in another. Row 56 and row 58 use the workflows of rows 26 to 30 (row 58 also needs one run from another directory). Row 57 needs something to continue in this directory; row 59 needs a directory with a subdirectory and a few small files.

## If `Ctrl+C` arrives as a signal

If row 1 ends the process (or prints `^C` and returns to the shell) instead of showing the hint, the console delivered a SIGINT and the raw-mode key never reached the keymap. Record that fact in the register with the terminal and Windows version. Per ADR-0115 §4 the signal path then applies there, and the two hosts end differently. In a **standalone chat** (`relavium chat`, and the plain and `--json` drivers of row 12) the first SIGINT ends the session cooperatively (abort, persist, exit code 4) and a second force-exits. In the **Home**, the chat it hosts included (rows 1 to 5, and the bare `relavium permissions` of row 16, which runs the Home), the Home's own signal lifecycle applies and the process exits `130` (`128 + 2`); the `4` is what a chat ends with, and inside the Home the mode loop consumes it ([home.md](../reference/cli/home.md#signal-lifecycle--exit-codes), [commands.md](../reference/cli/commands.md#exit-codes)). Rows 2 to 9, 15 to 22, 25, 30, 41, 45, 51 to 53, 56 and 57 (the `Esc` and `Ctrl+C` rows that close a screen, a popup or a card, the hosted run's two-press cancel, row 25's two `Ctrl+C` presses on the work page, which open the exit-guard card only as a key and not as a signal, the Runs screen's `Ctrl+C` of rows 30 and 45, the inspection popup's `Ctrl+C` of row 41, and row 42's `Ctrl+C` in the `/run` form opened from `/workflows`) are then expected to differ, and the register notes which ones. It is not a defect in the keymap, but it is a documented platform difference the maintainer decides what to do about.
