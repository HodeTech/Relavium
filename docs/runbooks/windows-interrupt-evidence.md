# Collect Windows evidence for the interrupt keymap

- **Status**: Manual acceptance recipe for [ADR-0115](../decisions/0115-one-interrupt-keymap-for-the-interactive-cli.md) §5, and (rows 13 to 16) for whether a Windows terminal delivers the command card's `Ctrl+O` ([ADR-0118](../decisions/0118-a-command-outside-the-allowlist-asks-instead-of-failing.md) §1) and the `/permissions` sheet's `d`, `Delete` and `Backspace` ([ADR-0137](../decisions/0137-permissions-is-a-sheet-and-esc-steps-back-out-of-the-full-view.md) §2), and (rows 17 to 19) for the keys of a workflow run hosted in the Home: the two-press cancel, `Esc` leaving the view, and a card that stays until it is dismissed ([ADR-0139](../decisions/0139-a-workflow-run-is-hosted-inside-the-home.md) §5), and (rows 20 to 24) for the keys of a parked run's cards: `↓` and `Enter` on an Attention row, the `Ctrl+Y` and `Ctrl+N` chords of the gate and budget cards, and `Esc` and `Ctrl+C` leaving a card ([ADR-0139](../decisions/0139-a-workflow-run-is-hosted-inside-the-home.md) §4), and (row 25) for the exit-guard card's `Ctrl+Y` and `Ctrl+N` ([ADR-0139](../decisions/0139-a-workflow-run-is-hosted-inside-the-home.md) §6), and (rows 26 to 30) for the keys of the Home's tab host: the tab keys, `p`, `r` and `x` on a Defined row, the History list's paging and filter keys, the run detail's `Enter`, `n`, `p` and `Esc`, and the node page's scroll keys, `n` and `Esc` ([ADR-0140](../decisions/0140-management-browsers-the-run-drill-down-and-the-durable-run-detail.md) §1, §2). No Windows pseudo-terminal harness exists (one would be a new dependency and needs its own ADR), so the evidence is collected by hand on a Windows machine and recorded in the phase register before MVP-4's final review round.
- **Date**: 2026-11-19 (rows 17 to 19, rows 20 to 24, row 25 and rows 26 to 30 added 2026-11-23)
- **Related**: [the interrupt keymap](../reference/cli/chat-session.md#the-interrupt-keymap--mvp-4-adr-0115), [the Home's keys](../reference/cli/home.md), [the continue checkpoint](../reference/cli/chat-session.md#the-continue-checkpoint--mvp-4-adr-0136)

The keymap is decided in one pure reducer and is covered by automated tests on every platform. What a test cannot show is what a **Windows console** actually delivers: whether `Ctrl+C` in raw mode arrives as a key (the keymap applies) or as a SIGINT (the signal path of ADR-0115 §4 applies instead). This recipe records which one it is, and that the keymap still behaves as designed under it.

## What you need

- A Windows 10 or 11 machine, a built `relavium` (the installed package or `node apps/cli/dist/index.js`), and a provider key in the Windows credential store.
- **Two terminals**, one each from: Windows Terminal (PowerShell) and the legacy console host (`cmd.exe` in a classic conhost window). Repeat the checks in both; the answer can differ.
- A throwaway directory as the working directory. Row 10 needs a `.relavium/project.toml` in it (create the file; nothing else about a project is needed).
- Use a small, quiet model; the turns below are one line each.
- Rows 17 to 19 need a workflow in the throwaway project that **runs long enough to press keys in** (a minute or more: a chain of agent nodes on a small model, each asked for a few hundred words), and the `/run` card flow of the Home (`/run`, pick the workflow, answer its inputs, choose *Yes* at the confirmation). A second terminal runs `relavium status <run id>` (the id is in the view's title) to see what the run is doing without going through the Home.
- Rows 20 to 24 need two more workflows in the throwaway project: one with a `human_gate` node (`gate_type: approval`) after a short agent node (the run pauses at the gate), and one whose workflow `budget` is so low that its first agent step pauses at a budget gate (use a small model). Start each with `/run`; the run view shows `‖ paused` when it parks. The Home must be opened in that directory: a run of another directory has no row and no card.

- Rows 26 to 30 need, in the throwaway project, **a workflow that finishes** (one short agent node), **a workflow that fails at its second node** (for instance a `transform` that refuses its input, after an agent node that succeeds), **a workflow whose agent node retries and then succeeds** (a node `retry` budget above zero and a task a small model sometimes gets wrong, or a tool that fails once; if none can be produced, record row 30's retry check as unrun), and **one node whose answer is long** (ask for sixty numbered lines). Run each once from the Home with `/run`, so that History lists finished runs of this project. The Home must be opened in that directory: History lists this project's runs first.

## If `Ctrl+C` arrives as a signal

If row 1 ends the process (or prints `^C` and returns to the shell) instead of showing the hint, the console delivered a SIGINT and the raw-mode key never reached the keymap. Record that fact in the register with the terminal and Windows version. Per ADR-0115 §4 the signal path then applies there, and the two hosts end differently. In a **standalone chat** (`relavium chat`, and the plain and `--json` drivers of row 12) the first SIGINT ends the session cooperatively (abort, persist, exit code 4) and a second force-exits. In the **Home**, the chat it hosts included (rows 1 to 5, and the bare `relavium permissions` of row 16, which runs the Home), the Home's own signal lifecycle applies and the process exits `130` (`128 + 2`); the `4` is what a chat ends with, and inside the Home the mode loop consumes it ([home.md](../reference/cli/home.md#signal-lifecycle--exit-codes), [commands.md](../reference/cli/commands.md#exit-codes)). Rows 2 to 9, 15 to 22, 25, 26 and 30 (the `Esc` and `Ctrl+C` rows that close a screen or a card, the hosted run's two-press cancel, row 25's two `Ctrl+C` presses at the landing, which open the exit-guard card only as a key and not as a signal, the tab host's `Ctrl+C` of rows 26 and 30, and row 27's `Ctrl+C` at the launch form's first field) are then expected to differ, and the register notes which ones. It is not a defect in the keymap, but it is a documented platform difference the maintainer decides what to do about.
