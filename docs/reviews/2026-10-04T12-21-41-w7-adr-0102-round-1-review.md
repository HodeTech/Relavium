## Findings and correction

The same ordinary declaration can appear in native `tools[].functionDeclarations[]` and
`responseJsonSchema`. Gemini's actual converter retains the latter reference, then replaces the
declaration's `parameters` with its converted schema. Separate copies change the response-schema
body from the existing converter's `OBJECT` to `object`. Both reviewers independently trace the
same installed SDK source; the parent separately confirms three actual offline SDK HTTP bodies in
its own guarded runtime root: original shared graph, independent copies and fresh shared working
graph. This parent probe covers generate only; it is not either reviewer's runtime evidence or the
future generate-and-stream acceptance.

The revision requires iterative memoized capture and whole-envelope mutable working copies which
preserve shared references across fields. Active ancestor cycles remain distinct from completed
aliases. Capture must avoid recursive depth failure and avoid multiplying distinct containers in
shared ignored graphs; no new depth/size limit is introduced. SDK working copies remain isolated
from caller/owned data and other attempts. Frozen inert caller data is explicitly supported, with
the corresponding change to former SDK mutation failures disclosed.

Incoming prepared plans must be validated against original controls/routing, or an existing accepted
factory-owned view, before projection replacement. Matching measured plans retain their captured
serializer value and ceiling without recapture. Factory association and post-selection binding do
not let a genuine mismatched plan manufacture a match. Descriptor separation precedes non-cap
getter invocation; quote applicability/exclusions retain their existing fail-closed rules.
