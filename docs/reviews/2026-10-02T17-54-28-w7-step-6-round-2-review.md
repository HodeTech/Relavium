## Findings and corrections

1. **High — primitive BigInt escaped JSON capture.** JavaScript invokes
   `BigInt.prototype.toJSON` even for a primitive. A native `1n` bypassed capture and reserved
   configured 17, then serialized as 200,000 after the credential resolver changed its closure.
   Actual OpenAI HTTP controls reproduced both native keys on both paths. A plain BigInt also
   failed only inside SDK serialization instead of the promised pre-admission typed refusal.
   [Shared cap capture](../../packages/llm/src/output-cap.ts) now includes surviving BigInts:
   valid serializers run once under the original key, while genuine serialization failures
   refuse before admission. Discarded BigInt remains inert.
2. **High — Gemini refused fields its SDK discards.** OpenAI-only native cap names were
   JSON-captured even though the installed Gemini SDK removes them before HTTP serialization.
   A cycle under either name made a previously sendable canonical-cap request fail. Actual SDK
   controls reproduced both paths. The same shared reconciliation now discards those foreign
   controls without executing their serializer. This differs from DeepSeek's forwarded modern
   key, whose value still requires capture despite not supplying official cap evidence.
   New [actual Gemini HTTP tests](../../packages/llm/src/adapters/gemini-output-cap-wire.test.ts)
   pin native/authored/uncapped parity, catalog-refresh handoff, serializer mutation and discarded
   cycles, throwing serializers and BigInt with an authored or absent cap.
3. **High — authored output schemas were omitted from priced input.** A parsed 40 KB workflow
   sent a 40,093-character schema through the actual OpenAI SDK while estimating ten input
   tokens, exactly as for an empty description. A 1,000-microcent cap therefore admitted it at
   the synthetic rate of one microcent per estimated input token. This is an omitted structured
   input, not a measured provider-token claim or media/tokenizer calibration finding.
   [EstimateTokensInput](../../packages/llm/src/types.ts) now carries the optional seam response
   format; the [shared estimator](../../packages/llm/src/request-estimator.ts) counts its complete
   JSON floor and preserves per-unit serialization fallback. The
   [turn](../../packages/core/src/engine/agent-turn.ts) measures the constructed current-round
   request, retaining the established conservative pre-strip rule. Absent/text formats add
   nothing. Canonical seam, hook and workflow contracts, plus dated ADR-0096/0101 notes, describe
   the correction without rewriting historical decisions.
