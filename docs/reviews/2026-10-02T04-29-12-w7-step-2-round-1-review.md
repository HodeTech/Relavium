## Findings

### High — an outer rollback could erase an issued key

The [allocator](../../packages/db/src/session-effect-turns.ts) returned key 1 from inside an
outer Drizzle transaction while the native connection remained in a transaction. Throwing from
that outer callback rolled the high-water update back; the next top-level allocation returned
1 again. Even an outer `BEGIN IMMEDIATE` cannot make a nested savepoint release durable.
This violated [ADR-0098](../decisions/0098-a-session-effect-row-holds-no-result-and-never-replays.md)'s
never-reused identity contract.

The parent independently reproduced it with the committed built package, then with the actual
allocator source pinned to `1927daa1`, transpiled into an owned temporary module. Reservation
now refuses an already-open transaction with the fixed typed code `transaction_active`. The
public Drizzle handle retains its existing native-client property in its type, rather than
using an unsafe cast or driver internals. Regression tests cover deferred, immediate and
exclusive outer transactions, rollback, an unchanged mark, and subsequent top-level issuance.
The current built allocator refused the same predecessor probe before issuing a key.

### Medium — session media metadata admitted unsafe integers

The new [session media schema](../../packages/shared/src/content.ts) inherited validators
that admitted `Number.MAX_SAFE_INTEGER + 1` for `byteLength` and `durationMs`, despite the
[canonical safe-integer contract](../reference/shared-core/database-schema.md#session-content-parts).
The reviewer independently persisted and reloaded those unsafe values through SQLite; the
parent reproduced schema acceptance in the committed built package.

Both fields are now capped in the session-only schema, preserving their sign constraints.
Direct schema tests and store write/read regressions reject unsafe values and retain the
maximum safe integer. The generic durable media union remains unchanged, pinned by a test.
