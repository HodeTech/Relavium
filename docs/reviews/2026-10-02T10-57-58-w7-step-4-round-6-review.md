## Process-exit qualification

The compiled entry assigns `process.exitCode`; native Node stdio can keep its process alive until an already
queued output write drains. A matched control externally bundled the exact `49d154e0` pre-step production
entry and reproduced the same plain/JSON delay with no effect rows or disclosure and an equal-size stderr
prefill. The parent independently reran that valid control. This is inherited process I/O behaviour, not a
new W7 cancellation or deletion regression. An earlier exploratory control accidentally issued a second
SIGINT and was excluded; the final rerunnable control uses exactly one.

Acceptance guarantees command/session/database/MCP teardown despite a blocked diagnostic write. It does not
claim the bin process has exited before pending native stdio drains, nor discard queued bytes or force an
exit that could truncate the JSON terminal. The canonical [journal contract](../reference/shared-core/effect-journal.md#8-needs_attention)
now states the distinction explicitly. No new architecture decision was needed.
