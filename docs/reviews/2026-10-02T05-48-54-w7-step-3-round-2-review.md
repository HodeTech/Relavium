## Findings

### High — a cached command key bypassed the durability latch

Both reviewers independently reproduced the same path through the real CLI host, built-in registry,
SQLite persister and effect journal: two completed turns, an idle `!` command caching key 3,
a failed `/trim` persistence write, then another `!` command. The persister had latched failure,
but the second command ran and committed negative slot -2. The
[engine's cached-key return](../../packages/core/src/engine/agent-session.ts) skipped the
persister allocator's refusal, and the [host effect port](../../apps/cli/src/chat/session-host.ts)
had no independent durability admission check.

The parent independently ran the retained reviewer probe and added a real host/SQLite regression;
it failed before correction. A second regression established the adjacent timing window: the first
provider attempt's cost write could latch failure immediately before its MCP tool call, yet the
effect still dispatched. That regression also failed before correction.

The host now checks the current attached probe at each effect preparation, independently of key
allocation or caching. Refusal is typed, non-retryable and non-recoverable, with the same fixed safe
message as provider admission. A refusal writes no new journal row and preserves the cached key.
Settlement/discard of an already-prepared effect remains available. The corrected tests prove no
second process spawn, no extra key, and no MCP dispatch or continuation after the cost-write failure.

### Medium — a recovered filesystem denial lost the resolved tool name

The contracts reviewer reproduced a real sandboxed `read_file('../outside.txt')` scope denial,
followed by model recovery. The host's typed `FsScopeDeniedError` deliberately carries no `toolId`.
The [structural producer](../../packages/core/src/engine/agent-turn.ts) required that field,
so it persisted `unknown_tool` with the now-correct `denied` outcome. Export consequently omitted
the actual tool from the completed turn's tool union.

The parent reproduced the issue with a real jailed filesystem, an owned temporary workspace and
SQLite persistence. The regression failed before correction. The producer now verifies exact
registry membership before using the call name when the host error has no id; an unknown-tool
error still uses the fixed marker. Core and CLI regressions pin the name/outcome and exported
grant, with provider id, path and host-content sentinels absent from stored structure and YAML.
