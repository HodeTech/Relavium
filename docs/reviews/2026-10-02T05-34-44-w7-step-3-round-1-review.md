## Findings

### High — byte measurement could abort a valid correction

The [turn producer](../../packages/core/src/engine/agent-turn.ts) measured structural argument
size with recursive `JSON.stringify` after dispatch. A valid 30,007-byte JSON argument with
15,000 nested arrays, sent to the real empty registry, recovered from the unknown-tool result
and completed without session history. Enabling structural history instead stopped after the
first provider call with `tool_failed`: the JavaScript serializer exceeded its call stack.
New metadata therefore changed execution and prevented an otherwise completed turn.

The parent independently ran the reviewer's built-module probe and added source regressions
for both deeply nested arrays and objects. Both failed before the correction. The internal
[byte counter](../../packages/core/src/engine/session-json-bytes.ts) now uses native JSON
encoding for ordinary values and an iterative plain-JSON count when necessary. Native encoding
still owns primitive/key escaping; an ancestor set distinguishes cycles from repeated references.
The fallback does not guess exotic/custom-hook serialization. Tests compare ordinary and deep
paths against native encoding for Unicode, escaping, numeric forms, omitted properties and array
holes; absent result remains zero. No raw value or digest enters structural history.

### Medium — a recovered policy denial lost its classification

The producer derived structural outcome from `isError` alone. The real registry and built-in
`read_media` produced a recoverable `ToolPolicyError(media_scope_denied)`; after the scripted
model recovered, the terminal history recorded `error` rather than `denied`.

The parent independently ran both the original typed-error probe and the strengthened real
built-in probe. The existing scope-recovery test now includes session history and asserts denial
followed by success; it failed before the correction. Structural production preserves the
original `tool_denied` discriminant. Other recovered dispatch errors retain `error`, and fatal
dispatch failures still produce no completed-turn transcript. The
[canonical session content contract](../reference/shared-core/database-schema.md#session-content-parts)
states the distinction.
