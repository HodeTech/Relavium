## Verified High and correction

**High — an uninvoked host failure can fabricate paid usage and generated processing.**
The attempt catch includes `preAttempt`, credentials and host setup. `#emitFailure`
prices any normalized diagnostic usage without requiring the chain-owned
`providerInvoked` flag. Generate additionally treats diagnostic usage alone as
processed-response evidence and stamps the surfaced error `contentCommitted: true`.

Both reviewers and the parent independently reproduce the defect through actual built
public LLM exports and a real `CostTracker`. An offline official-route factory uses
an injected Fetch implementation; its `preAttempt` throws a genuine `LlmProviderError`
with nineteen input and seven output tokens. With one microcent per token:

| Observation | Generate | Stream |
| --- | --- | --- |
| Credential reads / Fetch calls | Zero / zero | Zero / zero |
| Chain-owned `providerInvoked` | False | False |
| Tracker increment | 26 microcents | 26 microcents |
| Attempt and surfaced diagnostic usage | 19 / 7 | 19 / 7 |
| Invented generated processing/commitment | Present | Absent |

The same failure occurs with retryable `transport`, affecting retry authority as
well as financial observation. Credential-resolver controls remain safe because
their existing boundary separately replaces such errors with fixed authentication
diagnostics.

**Impact qualification:** core ignores records with `providerInvoked: false` before
its cost fold. No bogus core/SQLite ledger row, budget debit or provider invoice is
established. The verified defect affects the public chain's tracker, attempt trace,
surfaced financial evidence and generated commitment.

The correction strips usage from detached diagnostics when the chain-owned invocation
flag is false, before pricing, observation and surfacing. Generated usage establishes
processing only after invocation. Diagnosis, private cause identity and existing host
control flow remain intact. Actual invoked failures, native stops and held terminal
usage retain their existing accounting and cancellation/deadline behavior. Guarding
only `tracker.record()` would leave fabricated quantities in the surfaced diagnostic
and is insufficient. The canonical [seam contract](../reference/shared-core/llm-provider-seam.md)
states the same boundary. No new architectural decision is required.

Before delivery, authority tests an isolated candidate with both conditions: 259
tests across five suites pass, including eight new provenance controls. On unchanged
HEAD, four pre-attempt controls fail while four credential controls pass. Candidate
source is then removed and exact reviewed bytes restored. This is causal evidence for
the proposed correction, not delivery to the shared checkout or fresh acceptance.
