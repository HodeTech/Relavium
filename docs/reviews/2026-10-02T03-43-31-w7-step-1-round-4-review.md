## Findings

**Medium — checking an inode and unlinking its pathname are separate operations.** On failure,
[capture](../../tools/overflow-capture/capture.mjs) compared the reserved descriptor's identity to
`lstatSync(out)` and then called `unlinkSync(out)`. A concurrent replacement between those calls
was deleted. A two-process offline probe paused after the real stat, replaced the path with a
user artifact, and allowed normal cleanup to continue. The runner exited 1 with the fixed transport
refusal and the replacement was absent. No filesystem error was invented.

The command now closes only its descriptor and never deletes the caller-selected pathname.
Portable Node offers no atomic compare-inode-and-unlink operation; another stat would repeat the
same flaw. A failed destination may remain empty or, after a local write failure, partial. The
[runbook](../runbooks/capture-provider-overflow.md) explains this and directs the maintainer to review
it and use a new destination for a subsequent attempt. Refused provider bodies are never written;
a saved artifact still passes the complete secret scan before any body write.

The [command smoke](../../tools/overflow-capture/check.mjs) retains pre-existing/replaced file tests,
checks that ordinary failures leave an empty destination, and adds delay-only scheduling of the
old last-stat window. With the fixed command there is no failure-path stat/unlink to schedule.
The parent separately ran that scheduling regression against `1d603048`: the real stat was reached,
normal unlink deleted the replacement, and the regression failed reading the missing file.
