## Context

The CLI was built one screen at a time and the dialects show. Measured on 2026-11-24 ([MVP-11 §2.1 and Appendix D](../roadmap/phases/mvp-11.md#21-why-now)): six ways of writing a key legend and about 56 hint-literal lines in 25 non-test files (a text search; the plan's "about 25 places" counted places, not lines); at least nine separate status-to-glyph tables; two host-glyph security sets (the core's refusal pattern and the CLI's blanking set), with the rail's `◉` in neither; six meanings of `Esc`, most unlabelled ([ADR-0137](0137-permissions-is-a-sheet-and-esc-steps-back-out-of-the-full-view.md) recorded them); six families of approval verbs; at least nine money notations; and slash commands that open whatever surface their author found convenient (a note in the conversation, a picker that replaces the screen, a docked sheet, a block under the Home strip). The palette's order is the registry's declaration order, so `/exit` is the first row of both palettes and `/` then `Enter` leaves the application on the Home (observed on the built CLI: exit code 0). Three remedies name a command that does not exist, is deprecated or is spelled differently from the command table, and about fifty strings inside the TUI name a shell command ([ADR-0122](0122-the-home-is-the-interactive-product.md) §6 forbids that for a remedy).

Every dialect is pinned by tests (about 330 lines in 51 files at the baseline), so the cost of fixing the language grows with every merge, and `relavium` is pre-1.0, so a key or a label changed now costs no migration. The maintainer asked on 2026-11-24 for popups for reports and settings, an ordered palette, a speaker marker and a reviewed first run, in one MVP ([D79](../roadmap/current.md#wave-gating-decisions) to D82).

The floor does not move: approvals are answered only by Ctrl chords, `Esc` and `Ctrl+C` never approve, the input guards, the measured-frame acknowledgement and the question card's label and gutter are unchanged ([MVP-11 §5.5](../roadmap/phases/mvp-11.md#55-security-invariants-the-floor-that-does-not-move) is the list). This ADR is presentation, wording and registry data.

## Decision

**One language for every CLI surface: meaning is shared and chords are bound per surface, the surface is chosen by who started the interaction, and everything that is said or drawn twice is said or drawn from one table.**

### 1. Who started it picks the surface

| Who started it, and what comes out | Surface |
|---|---|
| The **system** needs a decision or an opinion (an approval, the agent's question, a continue checkpoint, a run gate, a budget gate, an MCP consent, the exit guard) | **Sheet**: docked at the bottom, the conversation stays visible. On the Home the run gate, budget and MCP consent cards stay in the slot [ADR-0139](0139-a-workflow-run-is-hosted-inside-the-home.md) and [ADR-0140](0140-management-browsers-the-run-drill-down-and-the-durable-run-detail.md) give them and the exit guard replaces the prompt block; all of them wear the sheet's frame ([ADR-0147](0147-a-system-started-question-is-a-sheet-with-a-frame-and-a-wait-clock.md)) |
| The **user** asked, and the result is a report, a setting, a form or a picker | **Popup**: centred, with steps ([ADR-0148](0148-a-user-started-report-setting-or-flow-is-a-centred-popup.md)) |
| The user asked, and the content is long and browsable and the user works in it (the tab host, the run view, `/help` on the Home) | **Screen**: takes the body |
| The user is choosing a command while typing | **Palette**: part of the prompt |
| The user asked, and the result is one line | **Instant**: no surface; a transient notification where a result needs saying |

*Notification* is the output channel of an instant command or of a closed popup, not a class. It draws on the **hint row** (the last row of the prompt block) for about three seconds and replaces the hint for that time; it is never an absolutely positioned layer; it queues while any chord or secret surface (a sheet or a popup) is shown, so nothing paints over its rows. The registry stores the class of every command; a command cannot be added without declaring one, and a surface matrix test opens every command on every surface that offers it. The classes of every existing command are [MVP-11 Appendix A](../roadmap/phases/mvp-11.md#appendix-a--command-classification). `/workflows`, `/permissions` and `/help` exist on both the Home and a chat; on the Home they stay screens ([OD-21](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)), in a chat they are popups.

### 2. `Esc` has four classes, and the key line says which

| Class | Meaning | Examples |
|---|---|---|
| **Decide** | Reject and stop; something is answered or cancelled | the approval card (`Esc stops the turn`), the agent's question, the checkpoint |
| **Step** | Go back one level | the inspection popup to its approval; a popup's step; the tab host's detail to its list; `/permissions` with a withdrawal armed |
| **Close** | Nothing changes | the palette, a picker, a popup's first step |
| **Leave** | The surface closes and the work or the state stays; nothing is decided | the run view (`Esc leaves it running`), a gate card (`Esc leaves it pending`) |

The class belongs to the pair (surface, state), not to the surface: `/permissions` is *Step* while a withdrawal is armed and *Close* otherwise. Every legend names the effect of `Esc` in words (an `exitLabel` is a required field of the legend builder), and `Esc` never approves, as [ADR-0122](0122-the-home-is-the-interactive-product.md) §7.4 and [ADR-0115](0115-one-interrupt-keymap-for-the-interactive-cli.md) rule. The classes **name** what the keymap does; no key changes meaning. Where the native prompt's `Esc back · Ctrl+C leave` closes the form, the word *leave* is bound to the "the work stays" meaning only and the form's wording becomes *close*. In a filter box, `Esc` clears the text first and closes on the next press. The two instant commands that suspend the terminal (`/scrollback`, `/edit`) say how to return in their own prompt.

### 3. The legend grammar

Dim; ` · ` between items; `Ctrl+X` with a plus; lower-case imperative verbs; the key that leaves goes last and its effect is written; arrows are `↑/↓`. This is [ADR-0137](0137-permissions-is-a-sheet-and-esc-steps-back-out-of-the-full-view.md) §5's grammar, generalised. *(Refinement of OD-4's bracket rule, from the UX review: the plan said "a key that changes state is bracketed", which the frames do not follow.)* **Letters and Ctrl chords are bracketed** (`[d] withdraw`, `[Ctrl+Y] Allow`, `[v] full diff`); the universal keys (`Enter`, `Esc`, the arrows, `PgUp/PgDn`, `Home/End`, `Tab`) are written plain; **the verb always states the effect** (`Enter apply`, `Esc stops the turn`), so a reflex `Enter` that applies something says so. The question card's `↑↓`, the call list's `↑↓` and the gate card's third-person verbs (`approves`) move to it.

**One builder, golden first.** Every hand-written hint becomes a call to the legend builder (`{ keys, verb, role }` items, a separator and a free-text item, because about a third of today's hints are not of that shape: three-space bracket rows with capital verbs, sentences that contain keys, parked-run cues that list a variable number of parts). The change is made in two commits: first a **golden snapshot** of every producer's output by state, taken before any change, and the builder; then the wording changes, so that the golden's diff **is** the reviewable change. A legend is built from the same constants the reducer reads, so a hint cannot drift from its handler, and each key table has a test that presses every key it lists. *(Refinement: the plan said "equivalence first"; reproducing legacy shapes by design would bend the builder, a golden does not.)*

### 4. Approval words

Three families by concept and one class apart: **permission** (Allow once, Deny, Deny + reason, Allow + remember); **gate** (Approve, Reject); **confirmation** (Yes, No); **progress** (Continue, Stop here), which is a class apart because it decides nothing about authority. The exit guard (`Ctrl+Y` cancels the run and exits; the other keys stay) is a **confirmation**. The Accept/Reject pair of the planned VS Code extension's per-hunk review is that surface's own and is out of scope ([MVP-11 §10](../roadmap/phases/mvp-11.md#10-out-of-scope)).

### 5. The visual language

- **One glyph table**, one module, imported by every status table; each **status** role has a glyph, an ASCII form and a word that always stands beside it (a glyph is never the only carrier, including the step rail of a popup, which also says `step 2 of 3`; the rules, the rail line, the selection and speaker markers and the tool marker are shapes, not statuses, and carry no word). Until the close-out step moves them into the reference page, the plan's [§4.10](../roadmap/phases/mvp-11.md#410-the-visual-language) table and [Appendix B](../roadmap/phases/mvp-11.md#appendix-b--palette-orders) hold the cells and the row orders; this ADR records the rules. The roles and glyphs are [MVP-11 §4.10](../roadmap/phases/mvp-11.md#410-the-visual-language): completed `✓`, failed `✗`, paused `‖` (`⏸` retires), cancelled `⊘`, running `◐`, starting `◌`, pending `○`, current step `◉`, rail line `╌`, heavy rule `━`, thin rule `─`, selection `›`, your turn `›`, tool call `▸`; the table also lists the glyphs the code already draws and the plan omitted (`⚠`, the status dots). The ASCII forms are **one per role, distinct from each other, at most three columns (brackets included) and never a key label** (`[v]` is the approval's full-view key, so the plan's provisional `[v]`, `[x]` and `[||]` are placeholders); Step 3 fixes the cells and a test fails when two roles share a form. A human line that printed `⏸` (the shell's `status`, the gate prompt, the history list) changes with the retirement; machine output does not.
- **When the ASCII forms are used.** Where the code uses its plain forms today (`NO_COLOR` or `--no-color`, and a non-UTF-8 locale), which is the answer for a terminal configured for a CJK width as well. A switch of its own is Phase 2.6.L's; Step 3 verifies the trigger in the code before the table is written.
- **Selection** is one marker, `›`, and the selected row is also drawn inverse, because `>` alone could not tell a selected row from the prompt. In ASCII the selection and your turn both read `>`: the selection is `>` with inverse, your turn is `>` with bold, and the two never share a surface row.
- **"No colour" means colour only** ([OD-6](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). Bold, inverse and underline stay; `dim` is not relied on (it is dropped without colour today and its reliability is unverified), so hierarchy is also carried by words, position and bold. An empty `NO_COLOR=` is ignored, as the standard says; the Phase 2.6.L acceptance wording and the help text that say otherwise are the things to update. Bold is gated by one rule in one place.
- **Host glyphs.** The glyphs the host draws (rail, rules, frames, markers) must not be reproducible by model text where it is drawn next to them. The CLI's set contains the core's refusal set and **every glyph of the table**, including the rail glyph, `◐`, `◉` and `⇄`. *(Refinement of OD-7: the plan moved the base set into the shared package. The architecture review showed that this edits the engine's source although the engine does not change, and that the invariant needs no move.)* The base stays where it is, and an `apps/cli` test **pins the relation by behaviour**: it probes the core's refusal over the box-drawing range **and, in addition, `›`, `✎` and `█`**, and the CLI's blanking function over every glyph of the table, and fails when the table gains a glyph the CLI set does not follow. What the transcript guard blanks in model text is the **marker** glyphs only (`›`, `▸`, `⇄`, and the speaker marker's ASCII companion where the margin does not yet exist); blanking `✓ ● ─` in model text would damage ordinary output.
- **Untrusted strings.** Every string read from configuration, a project file, a catalogue or a remote source (a directory, a provider or model id, a workflow, agent or MCP server name, a tool name, a skip reason, a session title, stored model text shown in a preview, a provider's error detail, a path a model chose) goes through the inline sanitiser, host-glyph blanking and a length bound. **On any surface that also has a chord step** (the doctor's deep consent, `/run`'s confirmation, `/init`, `/import`, `/pricing`, `/export`) the full scrub of the run cards applies: host glyphs blanked **and chord and key tokens made inert**, so a repository's text cannot draw `[Ctrl+Y]` where a person decides. A separator the status line uses is neutralised inside a field value, so a model id or a directory containing ` · ` cannot forge a field. The new bracketed key tokens (`[d]`, `[r]`, `[b]`, `[p]`, `[c]`) answer nothing on a question card, so the core's refusal list does not widen; where a popup has a chord step the full scrub above covers them.
- **Widths.** The new glyphs measure one column and the ambiguous family the CLI already ships (`○ ● ◐ ━ ─ ‖ ▶ ■ …`) also measures one column in the width library the renderer uses; the risk is a terminal configured for a CJK locale, which the ASCII form answers.

### 6. The speaker marker

No role labels in the full-screen renderer ([OD-18](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). Your turn starts with `›` in the margin, in the accent, on its first line only, and its text is **bold**; the reply is plain and has no marker; a tool call has `▸` in the margin, dim; a notice has nothing and is dim. A wrapped line hangs under the text; one blank row separates turns. There is no tinted background (a tint is the first thing lost without colour and needs a terminal-background probe). The text forms (copy, `/edit`, `/scrollback`) keep today's `> ` prefix so the speaker survives where styling does not. **The inline renderer, which is the accessible mode, keeps the words `you` and `agent`** as a per-renderer rule.

**The margin is what makes the marker trustworthy.** Model text is laid out in the content column only and can never occupy the margin where the host draws its markers. Until the transcript grid builds that margin, an interim guard blanks the marker glyphs at the start of **every rendered display row, after markdown and wrapping** (a bold heading or a wrapped line can start a row with `›`), in the live stream, the inline lines and both the markdown and the plain paths; a quotation in a reply, which renders dim and unprefixed, is given a visible gutter so it cannot pass for a host notice. **The colour-off path is not claimed protected until the grid lands**: `>` and `-` cannot be blanked from model text, because they are ordinary characters. The grid is therefore part of this MVP, not a polish step.

### 7. The registry is one table that orders the palette

The registry (`apps/cli/src/commands/repl-commands.ts`) becomes **one `CommandDefinition`** (`name`, `effect`, `args`, `run`) with **placements per surface** (`home`, `chat`): each placement carries the group, the rank, the description, an availability function and the surface class. `availableIn` is derived. The Home's commands get real open bindings instead of the empty `run` and the regular-expression chain they have today, and a shrinking allow-list in the matrix test names the surfaces that still lack an opener. *(Refinement: the plan delivered the fields in three stages, which re-types the registry and its tests three times.)* `exitLabel` belongs to the legend and the popup spec, not the registry. The registry imports its chat-mode names from the shared package, not from the chat module, and a lint rule keeps the data modules free of `ink`, `react` and `node:` imports.

**Availability** is `{ enabled, reason }` over a small context `{ surface, hasSession, hasKey, hasSavedSessions, turnRunning }` that the host fills **from cached state only** (never from a port or the keychain at render time). `hasWorkflows` is not an input in v0.2.0 (the catalogue is behind an asynchronous port): `/run` stays enabled and its popup shows the empty state *(refinement: the plan dimmed `/run` with "the project has no workflow")*. A dim row is advisory; the handler re-validates when the command runs. **One pure function builds the effective rows once per state change**, and the palette's reducer and its view both read them, so they cannot disagree on the highlighted row.

The contract:

1. **The first row touches the prompt and the list runs away from it, on every surface** *(the maintainer's ruling of 2026-11-24, replacing the plan's "always reads top to bottom")*. On the Home the list opens under the prompt and reads top to bottom; in a chat it opens above the prompt and its first row is the one next to it, so it reads bottom to top. The default row and the best match are therefore always the row beside the prompt, and `/exit`, the last row of the order, is the row **farthest** from it (the bottom edge on the Home, the top edge in a chat). There is no wrap-around, `End` jumps to the last row, the `▲ N more` and `▼ N more` markers follow the direction the list runs, and when rows are short the group gaps give way first and **never** the `/exit` row.
2. **The default row is the first enabled row and is never destructive and never ends the session**, so `/` then `Enter` never leaves the application. A popup never pre-selects a change (the model popup opens on the current value).
3. **Intent order, not alphabet.** Home: *Work*, *Set up*, *Check*, *End*. Chat: *Model and behaviour*, *Context*, *Inspect*, *Take away*, *End*. The row-by-row orders are [MVP-11 Appendix B](../roadmap/phases/mvp-11.md#appendix-b--palette-orders) and are pinned by the registry tests; they change only with a recorded reason. *(Refinement: `/help` is listed, in *Check* on the Home and in *Inspect* in a chat. The plan left it "typed only", which makes the keys that only `/help` lists, such as `Shift+Tab` and `Ctrl+J`, undiscoverable and contradicts [ADR-0122](0122-the-home-is-the-interactive-product.md) §9.)*
4. **A command that cannot act is shown dim with its reason, never hidden** ([OD-13](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). The reason is written (`unavailable · no conversation to clear`) so that it reads without colour; the arrow keys skip a dim row; a typed exact name followed by `Enter` shows the reason as a notification and is never "unknown command". A command a surface does not offer at all is not listed, and typed there it answers with one line that names the surface that has it and opens nothing. **A pointer to a surface that cannot be reached from here** (a stand-alone chat has no Home) names it in words and may say `relavium` alone; no other shell command is named. With no provider key `/providers` leads the Home's list.
5. **The chat's palette lists the commands that act on the live conversation or the session's own settings** ([OD-2](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)): `/models`, `/mode`, `/effort`, `/thinking`, `/permissions`, context, inspect, take-away and end commands. Project and environment configuration (`/providers`, `/init`, `/import`, `/pricing`) is Home-only; the Home-hosted chat keeps `/resume`. The stricter reading (also removing `/models`, `/mode`, `/permissions` from a chat) is not taken: a user in a chat who wants another model would have no visible way.
6. A typed query keeps today's ranking (an exact name, a name prefix, a name containing the text, a description containing it); inside a tier the declared order holds, and commands that end a session or spend tokens come after the others, so a short query does not land on `/clear`, `/cancel` or `/compact`.
7. Non-interactive drivers (plain chat, `--json`, one-shot) keep running today's handlers; their help text is derived from the registry and so follows its new order, which is accepted and recorded. It goes to standard error today and no machine output changes.

### 8. Notation

USD in human text (`$0.1235`); a model's price reads `$3 / $15 per M` under a column header that says input and output per million tokens; raw micro-cents appear only in machine output; the budget gate's amount is shown exactly as frozen (display rounding must never understate an amount being authorised: this is the budget gate's **consent path**, so the helper is in a rigor increment). One helper each for money, time, identifiers and paths; a path is project-relative or from `~`, never absolute. At most three money notations remain (a USD amount, a per-million price, raw micro-cents in machine output). Descriptions are written once per surface and a hint is built from the registry the command runs from ([OD-14](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). A word drawn from an identifier is the display name everywhere (`Anthropic`, not `anthropic`).

### 9. Accessibility target

The inline renderer stays the accessible mode ([accessibility.md](../reference/cli/accessibility.md)). A measurable subset binds the whole CLI: readable without colour, usable at 80×24, keyboard only, a glyph never alone, every surface present in the inline renderer with the same content and keys, and nothing that repaints on a timer in the inline renderer. **Speaker and tool markers are forgeable on the colour-off path until the transcript grid lands** (§6), so that path is not claimed protected before it. The full-screen mode's exemption from screen readers is documented, not hidden, and the way to the accessible mode (`--no-alt-screen`, `[preferences].alt_screen = false`) is named in the README quick start, in `--help` and in `/help` ([OD-15](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)).

### 10. Boundary and process

The data modules (the registry, the glyph table, the legend builder, the word tables) import nothing from `ink`, `react` or `node:`; a lint rule restricts direct value imports by a named file list, and the later extraction to a shared package is then mechanical. No package is created now: a package needs a second consumer. A **surface matrix harness** (every screen × alternate screen and inline × colour and `NO_COLOR` × two sizes) is built as the first commit of the language step, with baseline rows for today's surfaces, so it is the safety net during the pin churn; each later step registers its rows. Every pull request of the MVP lists which rules of [MVP-11 §5.5](../roadmap/phases/mvp-11.md#55-security-invariants-the-floor-that-does-not-move) it touches and which pins it broke on purpose.

### Alternatives considered

- **Keep the dialects and fix screens one at a time.** Rejected: the pin count and the number of parallel tables grow with every merge; this is the cheapest moment.
- **A separate package for the language now.** Rejected: no second consumer exists (the desktop and the VS Code extension are not started); the import boundary makes the extraction mechanical later.
- **Move the host-glyph base set into the shared package.** Considered (the plan's OD-7): it edits the engine's source for an invariant a test can pin by behaviour. Not taken; revisit if a second consumer appears.
- **Hide commands that cannot act.** Rejected: [ADR-0122](0122-the-home-is-the-interactive-product.md) §9 and OD-13 want them found and explained.
- **Sort the palette by name or by use.** Rejected: nothing in the product measures use (no telemetry), and a name order puts `/clear` before `/doctor` for no reason a user can predict.
- **One top-to-bottom reading order in a chat too** (the plan's first design: the first row at the top of the list, `/exit` beside the prompt). Considered and not taken: the maintainer chose on 2026-11-24 that the first row touches the prompt, which keeps the default and the best match under the user's eye and gives both surfaces one rule ("the first row is beside the prompt"). The cost is that `/exit` is the top edge of a chat's list, last in the order but not at the bottom of the screen.
- **Role labels (`you`, `agent`) or a tinted background for the speaker.** Rejected for the full-screen renderer: labels cost columns on every turn, a tint is lost without colour. The inline renderer keeps words.
- **Bracket every key, `Esc` included.** Rejected: brackets mark the keys a person has to know to press; `Esc` is amber and says what it does.
- **The strict reading of "settings leave the chat palette".** Not taken (§7.5).

## Consequences

### Positive

- One place to say a key, a word, a glyph or a status; a new surface inherits the language.
- `/` then `Enter` is safe; the first-run promise ("never ends in a dead end") loses its wrong remedies and its shell commands.
- The tables become tests: the registry, the glyph table and the host-glyph relation each have a test that fails when they drift.
- A transcript whose speaker cannot be forged, once the margin exists.

### Negative

- **Pin churn.** Hundreds of word-for-word pins change. Mitigation: golden first, wording second, each pull request lists the pins it broke on purpose, and the floor pins are re-run on the new frames and never rewritten to pass.
- **Visible key and label changes before 1.0** (`⏸` becomes `‖`; legends are reworded; the palette is reordered). Mitigation: a "UX" heading in the release's changelog ([OD-16](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)); `--json` stability stated separately.
- **The ambiguous-width glyphs stay.** A terminal configured for a CJK locale may draw `○ ━ ‖` as two columns. Mitigation: the ASCII form (reached with `--no-color`), the width table and the terminal matrix of the close-out step; not solved here.

### Implementation note — 2026-11-27 (unit 9 built: the grid, and what replaced the interim guard)

The transcript grid of [§6](#6-the-speaker-marker) is built (MVP-11 unit 9; the record is [implementation-log.md](../roadmap/phases/mvp-11/implementation-log.md), "Unit 9"). The decisions stand; where the build differs from §5, §6 and §9 it is stated here.

- **The margin and the content column.** The chat is on the Home's grid: the content column starts at the Home's margin (6 columns for 80 to 99, 8 from 100) and is `min(96, columns − 2 × margin)` wide (68 at 80). The marker is a typed margin role (`yourTurn`, `toolCall`, `modelSwitch`, `agent`, `notice`), set only by the host from a closed union; the margin cell is composed from the glyph table and a closed word list and takes no row text, and the content cell is exactly the content column wide. A tool call is one row per call with `▸` (`->`) in the margin; one blank row precedes each turn and each reply (tool rows and notices hug the entry above); a wrapped line hangs under the text and never starts with the break space.
- **The interim guard is retired as a row guard, and something else replaced it (§5 "What the transcript guard blanks", §6 "Until the transcript grid builds that margin", §9 "forgeable until the grid lands").** The security sitting of the unit proved that the margin guarantee is exact in Ink's layout but **not on a terminal**: a character the layout library measures narrower than the terminal draws (a Hangul filler, a skin tone after a non-emoji base, a variation selector after a letter, a Thai AM, a non-flag regional-indicator pair, a lone surrogate, a tab) lets a row reach the right edge, and the terminal wraps its tail into the margin, where model text could stand exactly where the host's mark does. So three things hold the floor now: (1) a pure **screen filter** (`render/tui/screen-text.ts`) at the display boundary of every untrusted row (the transcript, the live tail, reasoning, tool rows, warnings, the notification, the intro, the `@` and history views, the attachment bar) that drops the fillers and orphan marks, drops or rewrites the width-unsafe classes so that both measures agree (verified against widths measured on tmux 3.7b), and expands tabs; (2) the marker glyphs `›`, `▸`, `⇄` are **blanked again on model-written rows** (the person's own turn too) as defence in depth, which draws a space in their place in ordinary text and in a drag-copy, while `/copy`, `/edit`, `/scrollback` and the plain driver keep every byte; (3) the approval card, a consent surface, **escapes** the same classes visibly (`<U+XXXX>`) instead of dropping them. On the screen a model row that begins `›` or `>` can no longer stand in the margin on tmux; the residuals are named: a ZWJ sequence on a terminal without ZWJ support, ambiguous-width characters in a CJK locale, terminals other than tmux (not measured), the flat text forms (documents, plain driver) where a model line `> x` still looks like the person's turn, and look-alike letters (Cyrillic, Greek) of the inline words.
- **Where the filter runs and what holds a row to one row (round 3, 2026-11-27).** A width change made after the layout broke the first version of the filter: a Thai or a non-flag regional-indicator row grew past the content column on a real terminal, the newest rows of an ordinary Thai reply were hidden on the alternate screen, and the acknowledgement of a notice could resolve while the notice was off screen. The rule is now: **anything that changes a width runs before the layout** (the hanging rows, markdown, the question card's text and the live tail are all filtered first; the live tail through a chunk-safe stream that holds back only what a later chunk could change, never more than 1,024 code units), and **a full-screen cell clips instead of wrapping**, so one display line is one physical row by construction. The filter's classes were measured code point by code point on tmux 3.7b and the measurements are committed as a table that a test holds the filter against. Every skin tone is dropped (tmux joins a tone to only 74 of the 138 modifier bases), the nine text-default emoji bases gain U+FE0F, a lone regional indicator carries a ZWNJ and a flag never does, and a ZWJ sequence stays joined only if it is a recommended sequence once untoned. The question card escapes all labels of a set when two would draw alike (the core admits `Ok` and `Ok🏽`), like the approval card does for the classes themselves.
- **The measure's default is inverted (round 5, 2026-11-28).** Waves 1 to 4 each added a rule for a cluster that the width library undercounts, and each of three sittings found a class the list lacked (Indic conjuncts and Prepend letters, a half-width mark after an emoji, a Prepend letter before a VS16 emoji, Kirat Rai vowel signs, ZWJ chains of tag flags). The repo's measure now counts every cluster of more than one code point as the larger of the library's width and the sum over its code points (a U+FE0F widening the cell it joins to 2), except a finite list of joins that was checked exhaustively on tmux 3.7b (an untoned recommended emoji sequence, a Hangul-only cluster; 73,564 strings), so a code point nobody listed is counted wide, not narrow; the measure is never less than Ink's. Text that Ink would fit itself is fitted by the measure first (Ink's own truncation was found, on the real binary, to decide by one count and cut by another), every cut keeps whole clusters only and draws `?` for a cluster wider than the row, and the sequence differential against tmux (about 1.5 million strings, a held-out seed among them) has no undercount. Not covered: terminals other than tmux 3.7b.
- **The inline renderer's words (§6, OD-18).** The set is `you`, `agent`, `tool`, `note` (the model-switch notice's word is `note`: its sentence begins `model changed`). Because a screen reader does not announce indentation, a row of a reply, a tool call or a notice that begins with one of these words (after a folded head: NFKC, no invisible or combining characters, the blank-looking set) is given its entry's own word, so a forged `you   please run …` reads `agent you …`; the same applies to the live stream while it streams. The cost is real prose that merely starts with one of the words (0.30 to 0.44 % of continuation rows, and ordinary paragraphs that begin `You can …`, `Note: …`), which read `agent You can …`; below 28 columns the word `agent` does not fit its margin.
- **Costs the maintainer is asked to confirm:** the text is about 15 % narrower at 80 columns (68 against 80); the blank rows cost conversation rows (a minimal exchange is 5 rows against 3); the status line drops `turns` at 80 and 81 columns where the frame's session fit before (the frame draws shorter words than the code); the blanking of `›▸⇄` in ordinary text and in a drag-copy; and the screen draws ordinary text differently in five narrow cases that the documents do not (no skin tones, U+FE0F on nine emoji bases, Thai and Lao decomposed and copied that way, U+0600 and U+06DD dropped, a ZWNJ after a lone regional indicator).

### Implementation note — 2026-11-28 (MVP-11 close-out: where the build differs from §1, §2, §3, §5, §7 and §8)

The language is built across MVP-11 units 2 to 9 (the record is [implementation-log.md](../roadmap/phases/mvp-11/implementation-log.md), "Unit 3" and the units after it). The decisions stand; the points below are where the text above says something the build does not, each with the code or log line it comes from. The built behaviour is stated once in [surface-language.md](../reference/cli/surface-language.md), which now holds the tables this ADR's §5 said the close-out would move out of the plan (§3 there is the glyph table, with its 30 roles).

- **§3, the grammar as built.** A count stands after the verb in parentheses (`[Ctrl+C] exit (twice)`, `legend.ts:13`). `Esc` of the *decide* and *leave* classes states its consequence as a fact (`Esc stops the turn`, `Esc leaves it running`); the other two classes are the words `close` and `back`; the approval's answer keys keep their capitalised words ([§4](#4-approval-words)).
- **§3, a locked key says `(wait)`.** The grammar gained one item the text above does not have: a key that its guard holds shut is drawn dim and its verb is followed by `(wait)` (`LEGEND_WAIT`, `legend.ts:40-56`). A surface sets it from its guard only (`waitMark`); nothing reads it back from a label. The lock is a **display value read beside the frame**, never a snapshot field (`ChordGuard.lockedUntil`, `chord-guard.ts:144-170`, `:273`), so the mark appears in one repaint at the moment the lock opens and nothing ticks; the fit rule never cuts the way back. The cards that show it are listed in [ADR-0147](0147-a-system-started-question-is-a-sheet-with-a-frame-and-a-wait-clock.md)'s note (the question card has none: it has a 250 ms settle and no lockout layer), and the guarded settings forms and the chord cards of the popups' flows show it too (`popup-reducer.ts:1052-1054`; `legend.ts:40-46` names `[Ctrl+Y] Create them (wait)`). Where a lockout runs from is the card's or the guarded option's **appearance**, not only the answer before it (`native-prompt-guards.ts:8-23`, `run-card-model.ts:254-265`): a key held through a card's opening never answers it, and a refused press restarts the wait.
- **§2, the filter box.** In the popup host `Esc` with text in the filter clears the text first and closes on the next press (`popup-reducer.ts:1006`: the legend says `Esc clear the filter`, then `Esc back`).
- **§5, the plain forms follow colour and nothing else.** The text said the ASCII forms are used "where the code uses its plain forms today (`NO_COLOR` or `--no-color`, and a non-UTF-8 locale)". The trigger is colour off only (`NO_COLOR`, `--no-color`, `FORCE_COLOR=0`); no code reads a locale, and a switch of its own stays with Phase 2.6.L (`glyphs.ts:11`, [commands.md](../reference/cli/commands.md#output-modes)).
- **§5, the host-glyph set holds every glyph of the table except three.** The roles `•` (`bullet`), `▲` and `▼` say `hostBlanked: false`: they are shapes that are also ordinary text, and the base never blanked them (`glyphs.ts:20`, `:107-111`).
- **§5, selection.** "The selected row is also drawn inverse" holds for every list but one case: a row that carries a colour **tint** (the work page's Attention rows) is selected by `›`, bold and its tint, with no inverse, because inverse would swallow the tint; without colour no row carries a tint, so the plain rule applies (`tintedSelectionEmphasis`, `selectable-text.tsx:43-58`). A surface whose body has no inverse cell by design says so in the matrix with a written reason (`backdropHasNoInverse`, `surface-matrix/registry.ts:97`, `run-cell.ts:140-141`).
- **§7, placements.** The placements are `home`, `standalone-chat` and `home-chat` (`repl-commands.ts:151-158`), and a placement also carries its class (`popup`, `screen` or `instant`: `repl-commands.ts:167`, `:205`). No command declares `screen`: the Runs screen and the run view are reached from the work page and from popups.
- **§8, paths.** A path is project-relative, from `~`, or **as given** when it is inside neither: it cannot be shortened without hiding where it is (`displayPath`, `notation.ts:434-446`).
- **§1, notifications.** While a popup is open its notification is drawn in the popup's own legend row, not on the hint row ([ADR-0148](0148-a-user-started-report-setting-or-flow-is-a-centred-popup.md)'s note of the same date).
