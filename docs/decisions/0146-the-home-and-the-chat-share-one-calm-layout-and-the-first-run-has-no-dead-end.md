# ADR-0146: The Home and the chat share one calm layout, and the first run has no dead end

Where the review refined an accepted decision the refinement and its reason are written in place and marked *(refinement)*. Nothing is implemented. D64 tier: milestone for the banner; **rigor** for the Home's layout (the exit guard and the measured frame), the chat's untrusted sinks and the first-run key path.

## Context

The Home is the interactive product ([ADR-0122](0122-the-home-is-the-interactive-product.md)) and the chat is where the work happens, and they were drawn at different times: the Home has a plaque banner, a welcome block and an example line; the chat has its own footer whose order and words differ (`model · cost · N turns · P% ctx · <mode> mode · effort`, with no provider), and a hint that says "to end" and never names the Home. The strip, once populated, takes the place the prompt has on the empty Home, so the prompt moves.

The first minute is the product's promise ("type `relavium`, start talking; it never ends in a dead end"). Tracing it through the code on 2026-11-24 found 21 defects ([MVP-11 §4.12](../roadmap/phases/mvp-11.md#412-onboarding-the-first-run)), and running the built CLI in a sandbox (a throwaway home, a stub keychain, no key typed) confirmed them on screen and added more: with no key, `Enter` builds a chat that fails with a one-row red line **cut at 80 columns before the remedy even starts**, and the typed text is gone from the prompt; after `Not now` on the environment-key consent a message fails although the key is in the environment; `Save it anyway` is pre-selected after a network failure; the environment key's consent card saves to the global config and picks a model without saying either; `/doctor` on a keyless Home prints `all checks passed` with no key check and refuses `--deep` ("start a chat to use them") to a user who cannot start one; the skip note is dropped, and `Esc` on the below-floor notice spends the offer for good. A Home frame is written and erased 8 to 9 ms before the first card. Three paths write different starter models for one provider.

Security reading added two hazards that today's native card already has and the redesign must not keep. **The setup opens by itself, so keys typed or queued before it appears can answer it**: a select answers on `Enter` with no dwell, quiet gap or typing history, and `Use it` is pre-selected, so a held or double-tapped `Enter` on the keyless Home can reach a **persistent write of the global config**. And **keeping the draft keeps whatever was typed**: a pasted API key would survive in the prompt and then be recorded in the history database, which is unencrypted and cannot be deleted; today the defect that loses the draft accidentally prevents that.

The maintainer chose the Home's look (the "calm rail" design, a left-hung rail and wordmark with a box-less prompt) on 2026-11-24 and asked for the first run to be reviewed against the new language.

## Decision

**The empty Home is six things: the wordmark, the rail, the prompt, the status line, one hint line and space. The Home and the chat share one grid, one prompt block and one status line. The first run is a popup over the Home that is in the first frame, that cannot be answered by anything typed before it, that keeps what the user typed unless it looks like a secret, and whose failures cannot be answered by reflex.**

### 1. The empty Home

Specified by [MVP-11 §4.7](../roadmap/phases/mvp-11.md#47-the-home) and its frames; the decisions are:

- **Left-hung, no centring.** Left margin 6 columns for 80 to 99 columns and 8 from 100; the rail is `columns − 2 × margin` wide (68 at 80), **capped at 96** ([OD-8](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). One 12-row block a little above the middle (the exact vertical formula is fixed in the Home step and drawn from the real arithmetic, not the frames); **inline draws no vertical gap**, so nothing blank is pushed into the scrollback.
- **Wordmark** `R  E  L  A  V  I  U  M` (two spaces between letters, 22 columns), bold accent. Letter-spacing is kept over a block font, which would take a fifth of an 80×24 screen.
- **Rail** `◉ ╌ ○ ╌ ○`: three nodes (left end, the middle column, right end), the first filled when there is nothing to continue. The tagline is split across the nodes, `Start as an agent` (strong), `Ship the workflow`, `Own every run`, each with a dim note. The last note is a promise about the local history, which is stored unencrypted and cannot yet be deleted, so its wording is revisited when retention lands.
- **Prompt:** box-less, `›` in the accent, a dim example (`summarize the files in this folder`) **inside the prompt row**, the cursor on its first letter, one thin rule under it. The example is **never sent**: the first keystroke replaces it, and **`Tab` fills it in** (the hint says so), so the one visible suggestion can be accepted without retyping (the analysis' "Tab to fill", which the plan had not carried). `Enter` on an empty prompt keeps what it does today (with a hosted run it opens the run view, without a key it opens the provider setup) and otherwise answers with a one-line notification instead of nothing. Without colour the example reads `e.g. …` (dim cannot be trusted) and **the cursor stays visible** (today it is invisible under `NO_COLOR`: observed).
- **No colour:** the ASCII forms of the glyph table ([ADR-0145](0145-the-cli-has-one-surface-language.md) §5); the shape of `*` and `o` tells the first node from the others.

### 2. One status line, in the Home and in a chat

`provider · model · mode · directory` on the Home, where the mode is the **startup default for the next chat**; the line says so with a label that covers the whole group (`next chat: anthropic · claude-haiku-4-5 · ask mode`), not a qualifier on one field; `effort` stays when set. In a chat: `provider · model · mode · effort · turns · cost · context%`; the provider is new and the order changes (today `model · cost · N turns · P% ctx · <mode> mode · effort`). Modes are written `<mode> mode` (`ask mode`, `auto mode`), so `auto` is spelled out even without colour and no mode is a bare word. **Truncation:** the directory is cut first (leading path elements become `…`); mode, effort and `auto` are **never** cut; a long model id is cut in its middle last of all; in a chat the order of loss is turns, then **context, then cost** *(refinement of OD-9's "turns, then cost, then context": cost is the signal a person watches against a budget, and the context figure reads `ctx 18% used` so it says which way it counts)*. The directory is project-relative or from `~`, never absolute. **No git branch in the first release**: reading `.git` is a new untrusted terminal input that needs its own bounded, sanitised design.

**Where the data comes from.** The Home controller holds none of provider, model or mode today. They are resolved **once** at start into controller state (provider availability is already computed before the first paint) and refreshed when a provider or a preference changes; in a chat the provider is resolved at session start and on a reseat. Nothing on the render path touches the keychain or the disk: the chat renders every 80 ms and a key read blocks the event loop. A key or a config changed in another terminal leaves the line stale until the next refresh, and the reference page says so. One pure model builds the line for both surfaces, with the truncation order under unit tests. Every string on the line (a directory name, a provider or model id read from configuration) is sanitised, glyph-blanked, bounded, and a separator inside a value is neutralised ([ADR-0145](0145-the-cli-has-one-surface-language.md) §5). Outside a sheet, the provider, the model and the mode are always on screen.

### 3. The populated Home keeps the prompt where it is

When there is something to continue, the **prompt stays where it is and the strip sits below it**, so the empty and the populated Home share one layout. `↓` moves into the strip, `Esc` returns to the prompt, and the hint changes with the focus (`↑/↓ select · Enter open the gate · Esc to prompt · Ctrl+C twice to exit`; a hint may run past the rail up to the terminal width minus the left margin); at rest it says how to reach the strip (`/ commands · ↓ open a parked run · Ctrl+C twice to exit`). The rail is not drawn. A palette over it opens downward and hides the strip while it is open, so the block never exceeds `rows − 1`; its 15 rows and the title, prompt, rule and legend around them need 21 of the 23 rows of an 80×24 terminal, so only two of the three group gaps fit and the gaps are the first thing to give way (never the `/exit` row). The exit guard replaces the prompt block as it does today; its position and its measured-frame check are **re-proved** because the order of the body changes. Below 80×24 the Home says to enlarge the terminal **or to use the non-interactive subcommands** (the analysis' K5), and it does not lose a typed draft on a second `Ctrl+C`.

*Open (the maintainer rules on acceptance):* **whether the one-line title the Home draws when the block is not shown (the populated Home, or `show_banner = false`) is the plain word `Relavium` or the spaced wordmark.** Recommendation: the spaced wordmark. The chat header carries the wordmark too (§4), so the plain word would be the one surviving dialect; the frames already draw it.

### 4. The chat's header, prompt block and hint

- **Header** (one line plus one blank): the wordmark on the left, the session title on the right. In the alternate screen it is the first child; inline it is printed once as the introduction, because inline has no fixed top row. The blank row stays at every supported size ([OD-9](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)): at 80×24 the transcript has 16 rows at rest. The session title is untrusted persistent text, sanitised, glyph-blanked and bounded.
- **Prompt block**, in the Home's order: a blank row, the prompt, a rule, the status line, the hint (5 rows).
- **Hint**, by state. Idle with an empty prompt: `/ commands · Ctrl+C twice to go back to Home` in a chat the Home opened (key, verb, destination), and `/ commands · /exit or Ctrl+C twice to end` in a stand-alone `relavium chat`. **With a draft** the hint is the draft's own (`Enter send · Ctrl+J newline · Ctrl+C clears the draft`, and on the Home `Enter start the chat · Ctrl+J newline`): a hint that says `Ctrl+C twice to go back` would be false there, because the first `Ctrl+C` clears the draft, and `Ctrl+J newline` is the only on-screen cue for a multi-line message.
- **The grid.** The margin column holds the markers, line numbers and glyphs of tool lines; the content column holds text; the wordmark, the prompt, the status line, the transcript text and the diff code start at the same column; a popup is as wide as the content column. Moving the speaker markers into the margin changes the transcript's wrapping, the inline `TranscriptLine`, the `/edit` and `/copy` document, the live stream's wrapping width and the mouse selection together, so it is **its own increment with its own review and a scoped security sitting**. It is part of this MVP: without the margin a reply cannot be kept from imitating a marker on the colour-off path ([ADR-0145](0145-the-cli-has-one-surface-language.md) §6). Before it, the chat step splits the transcript into **semantic rows** that are then rendered for display and for the text document, which is what makes the grid mechanical.

### 5. The keyless Home

With no provider key the status line is replaced by `No provider key yet · Enter to connect · /providers`, in the accent, not dim, and it **stays visible when a hosted run or a strip row has focus** (today it is suppressed there). The hint reads `Enter to connect a provider · / commands · Ctrl+C twice to exit`, and with text typed `Enter to connect a provider · your message is kept`. Nothing else changes: it is a state of the Home, not a screen. `/doctor` on a keyless Home reports **provider keys** as a warning (a presence check, [ADR-0148](0148-a-user-started-report-setting-or-flow-is-a-centred-popup.md) §8), and its deep tier is available on the Home, so the remedy it names exists on the surface that shows it.

### 6. The first run

- **The setup is a popup that is part of the Home's first frame.** The controller starts with the popup already open, so the terminal draws one frame, not a Home that is erased milliseconds later (observed today: 8 to 9 ms). It is the one popup the system opens itself ([ADR-0148](0148-a-user-started-report-setting-or-flow-is-a-centred-popup.md) §2 owns the exception). **It opens only when** no conversation, turn, card, sheet, palette or screen exists, **the composer is empty and has been idle**, and the terminal is at least 80×24; below that it waits **without spending its offer** (today `Esc` on the below-floor notice spends it and resizing up does not reopen it). The keychain and key probes already run before the first paint; their result is captured there, not read again when the popup opens. Until the popup host exists the native card stays and only its words change.
- **Nothing typed before it can answer it.** Keys that arrived before the popup's first measured and flushed frame are dropped and counted as typing; for a settle window (about half a second) after it appears nothing selects; and an answer that writes configuration or stores a key needs a key that arrived **after** the popup appeared, the same "no foreign key since it opened" rule as the doctor's `[d]`.
- **Steps, and `Esc` steps back.** The rail reads *Provider · Key · Done* and says `step 2 of 3`; the check is the key step's busy state; `Esc` at the key returns to the provider list; `Esc` at the first step skips, and a skip says so in one notification (`Setup skipped · /providers connects a provider any time`), which fixes today's dropped note. The first card's footer reads `Esc skip for now`.
- **The key step says what happens to the key:** `Stored in your OS keychain, never on disk. Sent only to api.anthropic.com, once, to check it.` The check says `Checking your Anthropic key · one request to api.anthropic.com`. The field is masked and kept out of React state, history, the transcript and error text, exactly as today, and cleared when the popup closes and on resize (which says `Resized · key cleared, paste it again`).
- **A failed check cannot be answered by reflex.** On a network or timeout failure the first row is **`Retry the check`** (the key stays in the secret buffer until the popup closes or is resized), then `Enter a different key`; `Save it anyway · not verified` is never pre-selected and sits last but one; `Esc` returns to the key step; its hint names how to verify later. *(Refinement: without a retry the user on a poor connection must paste the same good key again, which pushes toward `Save it anyway`.)*
- **Success shows the result and a next step:** `Connected · Anthropic · claude-haiku-4-5 · Type a message to start, or /init to set up this folder`; the Done step closes on `Enter` or `Esc`. `/init` is **named, not offered**: the recorded decision that no initialization prompt appears unprompted stands.
- **A message typed before any key exists is kept** ([OD-19](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)): the first `Enter` opens the setup and keeps the draft; when the setup closes the draft is in the prompt and **is not sent** (sending it on success risks sending to a model the user did not look at). **The exception is a draft that looks like a provider key** (matched against the key shapes of the redaction module): it is never restored to the prompt and never written to the input history; the key step offers it as the key to use. A message is never built into a chat that cannot start; a failed build for any other cause restores the draft and shows its failure **wrapped whole** (a notice is wrapped, never cut inside a remedy). When the environment holds a key the user declined, the failure says so instead of repeating "no key".
- **An environment key is a consent, and it says so.** `Use it` stays the first row; the step names the variable, the provider, the model that will be chosen and that the choice is saved to the global config; `Not now` is one `Enter` away and remembered for the process ([OD-23](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). **The affirmative row is answered through the approval card's input guards** (a dwell from the acknowledged frame, the quiet gap, the typing window that counts keys typed before the popup opened, and the lockout across the flow's steps), **not by a bare `Enter`**: it persistently writes configuration, and [ADR-0129](0129-the-approval-card-is-docked-bounded-and-says-only-what-matters.md) note 12 already rejected "a highlighted option and `Enter`" for exactly this typing-ahead reason. It is an authority widening and leaves the record it leaves today (the config file).
- **A locked keychain is said first.** `Enter a key` is not offered when the keychain was found unavailable (the key would be checked and then lost); the step offers `Retry keychain`, the environment-variable route named once, `Remember this and continue without a key` (the step says what is remembered), and `Not now`; the note that tells the user to `export` a variable in a shell is replaced by in-TUI wording.
- **One first screen, not two.** The automatic first-run card and the explicit `Providers` list that a keyless `Enter` opens are one flow with one set of words; the list's circular hints (`open /providers…` inside `/providers`) say `no key yet · Enter to add one`, the provider names are their display names, and the "First-run setup" sentence is shown only on a first run.
- **No remedy inside the TUI names a shell command or a command that does not exist** ([ADR-0122](0122-the-home-is-the-interactive-product.md) §6): the wrong remedies of the plan and the ones the review found (`/clear` in a stand-alone chat points to a `/resume` that is not there; the Home's `/doctor` description advertises `--deep`, which it refuses) are fixed; the pricing flags read `--input-price` and `--output-price`; text that names a shell command without being a remedy (the `/clear` and `/export` notices) is dropped from in-TUI notices, and the exit line printed to the shell after the TUI has closed may keep it ([OD-20](../roadmap/phases/mvp-11.md#72-decisions-od-1-to-od-23)). Commands that are shell-only by design (`relavium permissions revoke --all`, `relavium logs`) stay in a short, reasoned allow-list of the pattern test. A pattern test keeps the rest out.
- **The shell route is unchanged** (`provider set-key` takes the key on stdin only); a masked prompt for it is MVP-9's.

*Open (the maintainer rules on acceptance):* **whether an explicit skip is remembered beyond the process.** Today the offer returns on every launch until a key is stored or the keychain reminder is accepted, so a user who chose to skip meets it again each time (the keyless status line is already the standing call to action). Recommendation: remember an explicit `Esc` skip in the operator-owned onboarding state ([ADR-0112](0112-chat-network-grants-and-onboarding-state-are-operator-owned.md)) until a key exists or the user opens `/providers`. *Open:* **whether the three default-model paths agree** (the setup and the consent path write `claude-haiku-4-5`; an environment key with no configuration gets `claude-sonnet-4-6`). This ADR requires only that the model is **named wherever a default is chosen**. Recommendation: one starter table per provider used by all three paths, so the first answer does not depend on how the key arrived; the cheaper starter keeps the first minutes inexpensive and `/models` is one popup away.

### Alternatives considered

- **Keep the plaque banner and the welcome block.** Rejected: it is the busiest thing on the first screen and its words are a second tagline.
- **Centre the block.** Rejected: left-hung text reads the same at 80 and at 120 columns, and the prompt does not jump.
- **Send the draft when the setup succeeds.** Rejected (OD-19): the model it would go to was chosen a moment ago, unseen.
- **Pre-select `Not now` on the environment-key consent.** Considered; `Use it` stays first because it is today's behaviour and the step now says what it saves, and the guards make a reflex `Enter` harmless. If the usability run shows surprise it is revisited.
- **Answer the consent with `Ctrl+Y`.** Considered; the guards give the same protection without teaching a chord at the first minute.
- **A git branch in the status line.** Rejected for the first release (§2).
- **A full-screen first-run page.** Rejected: the Home behind the popup shows where the user is and what skipping leads to.
- **Warn when a pasted key looks like another provider's.** Candidate for the first-run step; decided at implementation (key formats change and a heuristic can block a valid key, so it would only warn).

## Consequences

### Positive

- The first screen says one thing and the promise holds: no lost draft, no cut remedy, no shell command, no reflex into an unverified key or a config write, no key left in the history.
- The Home and the chat read as one product: the same prompt block, the same status line, the same grid, a hint that names the way back.
- Everything the first run says about the key (where it is stored, where it is sent) is on screen before the user pastes it.

### Negative

- **Many pins change** (`R E L A V I U M`, `Welcome to Relavium.`, the hints, the palette-fit suites). Mitigation: each commit lists the pins it broke on purpose.
- **The 80×24 arithmetic is tight** (a palette plus the Home block totals exactly 23 rows). Mitigation: the surface matrix, the group gaps giving way first, and every measurement checked in a real terminal, inline and alternate.
- **The Home controller changes again** (it must hold the provider, model, mode and directory the status line needs, and the banner's height is written in three places). Mitigation: the status line's model is one pure function shared with the chat; the three heights become one constant.
- **A guard on the first-run consent makes the first minute slightly slower** (a half-second settle). Mitigation: it is invisible unless a key arrives too early.
- **The usability evidence is thin** (no users, no usage data). Mitigation: the protocol of [MVP-11 §2.5](../roadmap/phases/mvp-11.md#25-success-criteria) with volunteers; every statement about users is labelled a hypothesis.
