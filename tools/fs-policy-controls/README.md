# Filesystem policy causal controls

The post-publication recovery correction appends two controls to the earlier 99:
`media-temp-cleanup-winner` and `media-temp-cleanup-absence`. Both require the
directory-validation and native-rmdir race witnesses in the complete 23-case
temporary suite. The five existing temporary controls also run that enlarged
suite. The two processes use explicit native IPC barriers; ordinary I/O refusal
and normalized missing-directory disposition have separate listing cases. A
successful final rmdir counts one whole claim, while its losing peer reports
contention. Prior artifact counts retain their original source attribution.

`pnpm check:fs-mutations` runs the bounded ADR-0105 mechanism-removal matrix on
physical byte copies outside the checkout. `--mechanism <declared-id>` supports
local diagnosis and never reports whole-matrix completion.

Each declared mechanism requires fixed/red/restored runs, identical complete named
case inventories, an exact single source anchor, and the declared semantic assertion
marker in its named regression. Import, setup, signal and timeout failures cannot
certify removal. Shared ancestor controls must fail through both the real tool host
and DB `save_to` ports. The compact control-only case file complements the ordinary
native regression suites; it does not claim every filesystem operation is mutated.

The runner reuses the existing usage-control physical source fence and runtime
body-evaluation witnesses. Every workspace seam resolves to the copied current
source, including `@relavium/shared` and `@relavium/db`; installed dependencies are
linked for reads and verified unchanged. Source/HEAD/index digests are checked after
the run, so run this against a stable checkout. Tests never mutate developer sources.
No Windows-only test is selected; native Windows evidence has its separate gate.

The matrix also removes sensitive-workspace admission and reinstates the overly
strict CAS pathname/inode coupling. Real argv pre-composition witnesses and native
concurrent publishers/readers must then fail their named assertions. These guard
both confidentiality and the availability of legitimate cooperative storage use.

Additional controls remove zero-link pathname-snapshot admission and Windows
concurrent-winner verification separately. Deterministic native-file/fault fixtures
pin those branches on every CI OS; actual concurrent native publication remains a
separate control. They do not turn a simulated platform branch into Windows evidence.

Native canonical-root selection has its own removal control: retaining a legacy
synchronous alias spelling must break a real file read through the admitted policy.
Its deterministic alias fixture mocks the legacy resolver while retaining native
canonicalization and file access. The Windows job separately exercises the original
OS temporary-directory spelling; it does not guarantee an 8.3 alias is present.

Cooperating deletion has a separate removal control. A native unlink-entry barrier
must break both admitted-delete idempotence and the actual host-GC caller's orphan
phase continuation. Both named semantic failures are required; a failure in the
store-only case cannot certify that caller witness. Strict path/ownership and
non-missing I/O refusal controls remain in the same declared inventory.

`RELAVIUM_ACCEPTANCE_EVIDENCE=/absolute/directory` retains bounded JSON/JSONL/log
metadata under `filesystem/`, outside authored source. It excludes the copied graph,
cache, native databases and dependency bytes. Scratch copies are removed even on
failure. A passing matrix supplies causal evidence; independent implementation
review and the full required gates remain separate obligations.

The coordinator, process join and semantic outcome authority now live once in
[causal-controls](../causal-controls/README.md). This entry point remains a thin
filesystem wrapper retaining the original 26 mechanisms and their workloads, artifact directory,
process bounds and inherited filesystem environment. Both directories are included
in the physical source closure. Ancestor tool/save_to and delete/GC requirements
are explicit declarative witnesses, with no family special case in the authority.
This extraction does not relabel historical execution evidence.

ADR-0106 extends the same family with bounded media writes and reads, independent
byte/type verification, handle admission before durable publication, atomic SQLite
metadata, owner-qualified temporary cleanup, response header agreement and provider
selector preflight. The original 26 ADR-0105 controls remain declared. Parser controls
pin the object and inspection arenas, recognizer finish, finite structure counts,
WebM track/block counts, Ogg comments and PDF ID hex length. Borrowed URL chunks,
early upstream close, body abort and native HTTP close have separate controls. Each new
control runs an entire named regression file in fixed, removal and restored phases;
native child fixtures are part of the physical source graph and must join before a
phase completes. Native fixtures that launch their own Node programs use the same
source/dependency evaluation fence: their target and worker body records must share
the child PID, and the worker's installed dependencies must match the pinned manifest.
The complete per-PID evaluation receipts are retained byte-for-byte through bounded
gzip archives and an offset/hash index; the verifier reconstructs and checks every
original receipt without an unbounded decode. The mechanism inventory in
`mutations.mjs` and a completed retained `export.json` are the evidence for a
particular source head. An author-local fixed
test run or selected `--mechanism` diagnosis does not certify the full matrix.

The direct 4 KiB reader-request and 25 MiB skip exact/+1 cases pin helper contracts;
current admitted parser calls cannot request their over-limit values. Current MP4
and WebM grammars cannot reach their depth-16 checks, and the accepted PDF profile
cannot reach its 65,536-token count within the rolling tail. Those defensive guards
are not represented as hostile-byte removal evidence. The PDF tail's read-window
check remains a separate bound: a malformed over-tail input refuses even if that
one check is removed, so ordinary rejection alone does not certify it. Inspection
arena observation measures byte-array allocations, not the entire JavaScript heap;
these controls make no full-decoder claim.

R1 extends this same matrix with source-alias preflight, WebM ContentEncodings
refusal, and branch-output prestate publication. The branch removal requires both
its downstream first-byte witness and its independent 33-part pre-pull bound witness.
All earlier controls run their enlarged complete regression files, including the
new ordinary cases, in every phase.

ADR-0109 adds fifteen declared removal controls in this same family, retaining the
original 74 IDs and workloads. Shared helper controls distinguish prompt foreign
observation, cached native acknowledgement before re-entry, captured original
return/receiver, duplicate registration before a getter read, and late promotion
after getter re-entry. De-inline controls distinguish a prompt counted return from
the encompassing native join. Each real store has separate foreign-finite and
native-join removals; filesystem storage also requires local file/temp cleanup
before its source close. Native construction controls cover exact first-party
public-iterator registration and refusal to classify injected dependencies as
native. The finite adopted-EOF removal is explicitly a **trusted fixture-contract**
check, not a shipped product guard. Private memory block release before the join
is checked by source and ordinary behavior; no deterministic external removal
witness is claimed for that private storage reference. Built CLI packaging checks
are separate positive artifact evidence, not source-aliased removal controls.

The filesystem local-first control moves the source-close join into the producer's
verification-failure path, before publisher cleanup. The publisher remains awaited,
the original byte failure remains primary, and the complete six-case store cohort
must produce its named cleanup-order assertion with zero runner errors. The former
`return await` removal also abandoned the publisher Promise and broke natural EOF;
the corrected runner refuses that contaminated removal. Its historical capture is
not accepted as current evidence.

R2 appends four controls without changing the prior 89 IDs or complete workloads:
WebM and MP4 each lose only their repeated singleton-identity refusal, while
native HTTP separately loses raw `Content-Type` field preservation and the
post-normalization multiplicity check. The native header cases execute real
loopback responses and require both whole-buffer and filesystem-store named
admission failures; source/dependency receipts identify the launched worker.
The coordinator now checks every selected source anchor before the first fixed
phase and rejects effective case or configured hook timeouts above 15 seconds.

R3 appends one observer control without changing the earlier 93 IDs. It replaces
the complete captured-intrinsic observation block with the former own-`then`
assimilation expression. A source-aliased native worker runs foreign and registered
iterators through thirteen joined direct/store/de-inline scenarios per parent case.
Both complete parent cases must fail their named assertion when an original
rejected Promise becomes unhandled; fixture cleanup observes it only after the
diagnostic checkpoint. This is a finite Promise-constructor/species precondition,
not a universal interception claim.

The Windows temporary-claim repair adds a 95th control after that observer. It
removes exact native v2 claim-identity comparison by passing both sides through
Number's precision ceiling. The complete 19-case temporary regression requires a
different bigint inode with the same Number value to remain present and report
`identity_changed`; legacy v1 safe-token recovery and unsafe-token retention stay
in that complete workload. This controlled numeric collision is portable evidence,
not a measurement of a particular NTFS identity.

R4 appends a 96th selector control after the original 95. Its one-site removal
restores the prior image-else-audio nested OpenAI lookup for video. The complete
20-case provider selection file must produce named pre-entry failures for nested
`format`, `output_format` and `response_format`, with the installed SDK video call
and invocation-start signal still at zero in the fixed phase. The earlier native
selector control retains its full enlarged file. Exact per-phase source manifests
are now packed into one bounded gzip archive and offset/hash index only at export;
each runtime hash and the original manifest bytes remain independently verifiable.
R5 appends a 97th control for whole-buffer chunk ownership. A finite producer
reuses its admitted AAC bytes on the next pull; both a Node Buffer and a typed-array
subclass must retain the original returned bytes without invoking producer slice
or iterator hooks. Removing only the intrinsic typed-array copy breaks both named
cases; the ordinary Uint8Array control remains in the complete three-case workload.
No earlier ID, order or complete workload is removed.

R6 adds two controls for intrinsic configured-response byte accounting and buffered
chunk ownership. The complete 28-case file covers exact capacity, cumulative
overflow, inert length overrides on Uint8Array/Buffer, accessor non-evaluation,
producer reuse and both public media fetch paths. The first removal restores
replaceable length accounting and requires named direct and media refusals; the
second removes only the buffered copy and requires both reuse witnesses.
All original 97 declarations retain their IDs, order and complete workloads.

The earlier 99-control cohort projected 1,789 retained files. The current
declaration in `mutations.mjs` contains 109 controls /327 phases, projecting
1,969 retained files (109 × 18 + 7) under the unchanged 2,000-file /64-MiB
ceilings. This is capacity arithmetic, not a measured export or completed capture;
historical captures retain their own source heads and actual counts.

The declaration is not acceptance evidence by itself. The complete matrix
still requires a stable committed head, all fixed/removal/restored phases,
named semantic witnesses, child source/dependency receipts, byte-exact restoration,
the retained-evidence caps, and independent cumulative review.

`pnpm smoke:media-packaging` executes freshly built shared/core/db entry points and
the untouched CLI bundle in the required local and GitHub CI gates after build.
The workspace witness proves exact identity through raw store and engine de-inline
consumption; a physical second shared copy remains foreign, demonstrating the
unsupported cross-copy boundary. The CLI witness uses synthetic history and real
loopback HTTP/CAS failure with controlled native retirement. Its exact fixture HTTPS
dispatch is redirected at the native transport edge; it is packaging/lifetime proof,
not TLS or SSRF evidence. Missing artifacts refuse rather than skip. These artifact
checks are separate from source-aliased mechanism-removal certification.
