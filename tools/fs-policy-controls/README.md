# Filesystem policy causal controls

`pnpm check:fs-mutations` runs the bounded ADR-0105 mechanism-removal matrix on
physical byte copies outside the checkout. `--mechanism <declared-id>` supports
local diagnosis and never reports whole-matrix completion.

Each declared mechanism requires fixed/red/restored runs, identical complete named
case inventories, an exact single source anchor, and the declared semantic assertion
marker in its named regression. Import, setup, signal and timeout failures cannot
certify removal. Shared ancestor controls must fail through both the real tool host
and DB `save_to` ports. The compact control-only case file complements the ordinary
native regression suites; it does not claim every filesystem operation is mutated.

The runner reuses the existing usage-control physical source fence and runtime
body-evaluation witnesses. Every workspace seam resolves to the copied current
source, including `@relavium/shared` and `@relavium/db`; installed dependencies are
linked for reads and verified unchanged. Source/HEAD/index digests are checked after
the run, so run this against a stable checkout. Tests never mutate developer sources.
No Windows-only test is selected; native Windows evidence has its separate gate.

The matrix also removes sensitive-workspace admission and reinstates the overly
strict CAS pathname/inode coupling. Real argv pre-composition witnesses and native
concurrent publishers/readers must then fail their named assertions. These guard
both confidentiality and the availability of legitimate cooperative storage use.

Additional controls remove zero-link pathname-snapshot admission and Windows
concurrent-winner verification separately. Deterministic native-file/fault fixtures
pin those branches on every CI OS; actual concurrent native publication remains a
separate control. They do not turn a simulated platform branch into Windows evidence.

Native canonical-root selection has its own removal control: retaining a legacy
synchronous alias spelling must break a real file read through the admitted policy.
Its deterministic alias fixture mocks the legacy resolver while retaining native
canonicalization and file access. The Windows job separately exercises the original
OS temporary-directory spelling; it does not guarantee an 8.3 alias is present.

Cooperating deletion has a separate removal control. A native unlink-entry barrier
must break both admitted-delete idempotence and the actual host-GC caller's orphan
phase continuation. Both named semantic failures are required; a failure in the
store-only case cannot certify that caller witness. Strict path/ownership and
non-missing I/O refusal controls remain in the same declared inventory.

`RELAVIUM_ACCEPTANCE_EVIDENCE=/absolute/directory` retains bounded JSON/JSONL/log
metadata under `filesystem/`, outside authored source. It excludes the copied graph,
cache, native databases and dependency bytes. Scratch copies are removed even on
failure. A passing matrix supplies causal evidence; independent implementation
review and the full required gates remain separate obligations.

The coordinator, process join and semantic outcome authority now live once in
[causal-controls](../causal-controls/README.md). This entry point remains a thin
filesystem wrapper retaining the original 26 mechanisms and their workloads, artifact directory,
process bounds and inherited filesystem environment. Both directories are included
in the physical source closure. Ancestor tool/save_to and delete/GC requirements
are explicit declarative witnesses, with no family special case in the authority.
This extraction does not relabel historical execution evidence.

ADR-0106 extends the same family with bounded media writes and reads, independent
byte/type verification, handle admission before durable publication, atomic SQLite
metadata, owner-qualified temporary cleanup, response header agreement and provider
selector preflight. The original 26 ADR-0105 controls remain declared. Parser controls
pin the object and inspection arenas, recognizer finish, finite structure counts,
WebM track/block counts, Ogg comments and PDF ID hex length. Borrowed URL chunks,
early upstream close, body abort and native HTTP close have separate controls. Each new
control runs an entire named regression file in fixed, removal and restored phases;
native child fixtures are part of the physical source graph and must join before a
phase completes. The mechanism inventory in `mutations.mjs` and a completed retained
`export.json` are the evidence for a particular source head. An author-local fixed
test run or selected `--mechanism` diagnosis does not certify the full matrix.

The direct 4 KiB reader-request and 25 MiB skip exact/+1 cases pin helper contracts;
current admitted parser calls cannot request their over-limit values. Current MP4
and WebM grammars cannot reach their depth-16 checks, and the accepted PDF profile
cannot reach its 65,536-token count within the rolling tail. Those defensive guards
are not represented as hostile-byte removal evidence. The PDF tail's read-window
check remains a separate bound: a malformed over-tail input refuses even if that
one check is removed, so ordinary rejection alone does not certify it. Inspection
arena observation measures byte-array allocations, not the entire JavaScript heap;
these controls make no full-decoder claim.
